## A handler that takes 400 ms

*Why does a busy app no longer freeze the window?*

```mermaid
sequenceDiagram
  autonumber
  participant W as App thread
  participant L as Lock
  participant M as Engine thread
  participant E as Engine (Rust)
  W->>L: acquire
  Note over W: handler runs for 400 ms, holding the lock
  M->>L: tryAcquire → fails
  M->>E: pump: input, resize, scroll, repaint — no commit
  M->>E: pump again, still no commit
  W->>L: release
  M->>L: tryAcquire → succeeds
  M->>E: tick: the 400 ms of work lands in one frame
```
